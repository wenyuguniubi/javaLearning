# 阅读位置记忆设计

## 背景

复习册和训练台页面较长。用户重新打开或刷新页面时会回到顶部，需要反复拖动，也难以确认上次阅读位置。

## 目标

- 分别记住复习册和训练台的上次阅读位置。
- 直接打开或刷新页面时自动恢复。
- 显式章节链接优先于历史位置。
- 不增加按钮、弹窗、账号或后端服务。
- 不影响现有主题、掌握度与目录导航。

## 非目标

- 不同步不同浏览器或不同设备的阅读位置。
- 不提供多条阅读历史、书签列表或进度百分比。
- 不记录用户阅读时长。

## 交互规则

1. 复习册和训练台使用不同的位置记录，互不覆盖。
2. 页面滚动时以节流方式保存当前位置，离开页面时再保存一次。
3. 直接打开页面或刷新页面且 URL 不含章节锚点时，恢复上次位置。
4. URL 含章节锚点时，例如 `review.html#mysql-review`，优先定位到该章节，不恢复历史位置。
5. 保存的滚动位置仍处于当前页面有效范围时，恢复精确像素位置。
6. 页面结构变化导致像素位置超出范围时，若保存的章节仍存在，则定位到该章节顶部。
7. 没有历史记录或本地存储不可用时，保持浏览器默认行为。
8. 用户主动滚回顶部并离开后，顶部会成为新的历史位置。

## 数据设计

阅读位置使用独立的 localStorage 键，不修改已有 `java-interview-workbench-v1` 学习状态结构，降低对现有数据的影响。

每个页面保存：

```json
{
  "scrollY": 12840,
  "sectionId": "mysql-review"
}
```

页面键：

- 复习册：`java-interview-reading-position-review-v1`
- 训练台：`java-interview-reading-position-workbench-v1`

## 实现设计

在 `review.js` 与 `app.js` 中加入相同的小型位置管理逻辑，不新建共享脚本，避免为两处简单调用增加加载和依赖复杂度。

位置管理包含三个职责：

- 根据当前视口内章节确定 `sectionId`。
- 使用定时节流保存 `scrollY` 和 `sectionId`。
- 页面初始化时根据 URL 锚点和历史记录决定是否恢复。

恢复发生在 DOM 初始化完成后。设置 `history.scrollRestoration = "manual"`，避免浏览器自动恢复与应用恢复相互竞争。恢复使用一次延后到下一绘制周期的滚动，确保页面布局已经可用。

## 异常与边界

- localStorage 的读取、解析或写入失败时静默跳过，不阻断页面初始化。
- 无效 JSON、负数位置和缺失字段视为无历史记录。
- 精确位置上限按 `document.documentElement.scrollHeight - window.innerHeight` 校验。
- 如果保存位置超出页面范围，优先使用仍存在的 `sectionId`。
- 若 URL 只有无效锚点，也视为显式导航，不用历史位置覆盖用户意图。
- 滚动监听使用被动监听，并通过节流控制写入频率。

## 验收标准

1. 在复习册长章节中滚动后刷新，恢复到近似相同的像素位置。
2. 关闭页面再直接打开，恢复到上次位置。
3. 在训练台和复习册保存不同位置后，两页分别正确恢复。
4. 打开 `review.html#mysql-review` 时进入 MySQL 章节，不跳回历史位置。
5. 打开 `index.html#jvm` 时进入 JVM 模块，不跳回历史位置。
6. 滚回顶部后离开，再次打开页面时保持顶部。
7. 清除或破坏位置存储后，页面仍能正常加载。
8. 原有主题、掌握度、移动端目录与控制台均正常。
